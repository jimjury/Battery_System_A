# V3 修订：PC A 与便携式 C 部署（2026-11-26）

本修订由用户明确提出，对 V3 中仅以 ESP32 描述系统 A 的约束作以下扩展。其他多对多、逐对授权、插件化、隐私及真实测试要求继续有效。

1. A 是逻辑客户端角色，有 ESP32 A 与 PC A 两种实现。保留 ESP32 原工程；新增目录 `AI_Platform_PC`，其中 `desktop_a` 为纯电脑 A，不需要 ESP32、USB 数据线或固件烧录。
2. PC A 使用电脑自己的网络主动连接独立 C，再通过 C 发现/配对 B、获取模型/权重元数据、上传数据、创建任务、查询和导出。浏览器仅访问本机回环服务，C 凭据保存在本地私有运行目录。PC A 不在浏览器直接保存设备凭据，不通过 GitHub Issues/仓库文件代替私有任务通信。
3. ESP32 A 继续使用 USB 本地网页 + ESP32 独立 Wi-Fi，禁止共享/NAT 规则保持。PC A 使用本机正常网络，不要求模拟 USB 或改系统网络；相应 USB/分区/烧录验收仅适用于 ESP32 A。
4. A/B 仍通过唯一 UUID 与 C 登记，逐对授权可撤销；PC A 与 ESP32 A 享有相同角色契约。不能因为 PC 性能更高而绕过 C 权限，也不能以 PC 测试冒充 ESP32 硬件验收。
5. C 部署在用户授权的独立服务器。GitHub 保存源码、发布包、执行 CI/部署流程，不作为持续运行的 C API/数据库/MQTT 服务器。当前授权测试主机为 60.204.129.7，域名暂缺，使用 IP + 项目专用 CA，PC A/B 显式信任该 CA；不得禁用证书验证。主机地址属于部署配置，不写死平台协议。
6. C 提供可迁移的源码部署包、SHA-256 清单、现有 Python 检查、独立服务账户、systemd 启停、自启、升级前一致性备份、启动健康检查和失败回退。私有数据库/文件/凭据与不可变源码版本分离。迁移时同时迁移私有数据和 TLS 身份，停旧实例后切换，禁止覆盖未知现有服务。
7. 新服务器不要求重装 PC 的 Python/IDF/Conda，不安装模型训练环境。C 不运行科研模型。模型执行和已训练权重保留在 B，真实模型缺失时只运行显式标记 demo 的实际插件测试。
8. 所有测试记录区分：单元/协议替身、本地实际 A-C-B 服务、真实公网 C 链路、实际浏览器、真实模型和 ESP32 实机。40 项验收增加 PC A 适用性列；PC 链路通过不使硬件、MQTT 或 SOC/SOH 项自动通过。

执行顺序：新目录隔离 → PC A 本地真实 HTTP/worker 与浏览器验证 → C 云端安装 → PC A/本机 B 经真实云 C 联调 → 部署/升级/恢复与权限负例 → 更新记录及源码。未经用户恢复授权，不进行 ESP32 首次烧录。
